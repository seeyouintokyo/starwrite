# Starwrite

Starwrite 是本地文件驱动的内容生产主控 Skill。它不依赖某个 Web App，也不把凭证写进项目；一次任务对应一个独立文章项目目录。

## 三种入口

先确认用户提供的是哪一种，再建目录。除非用户明确要求，不混用入口。

1. **已有素材**：网页、访谈、笔记、RSS、文档、视频或播客。
2. **只有选题**：先做检索和事实核验，再起稿。
3. **已有初稿**：先核验关键事实和来源，再改写、排版与发布。

面向用户交付的文件一律使用中文名称，并平铺放在同一个文章项目文件夹。上游工具必需的 CSS、脚本和图片资源只能放入 `_资源/`；不得再建立多个面向用户的分类目录。

统一目录：

```text
文章项目/
├── 任务说明.md
├── 素材整理.md
├── 事实卡片.md
├── 研究记录.md
├── 文章母稿.md
├── 短视频脚本.md
├── 公众号排版.html
├── 录屏幻灯片.html
├── 公众号缩略封面.png
├── 信息图卡-01.png
├── 信息图卡-02.png
├── 信息图卡-03.png
├── 发布结果.md
├── 交付清单.md
└── _资源/
```

`文章母稿.md` 是唯一内容母稿。公众号 HTML、短视频脚本和录屏 HTML 都从它派生，不各自重写事实。

## 配置向导

任务需要 UniFuncs、图片 API 或公众号草稿箱而配置缺失时，先读取 [configuration.md](references/configuration.md)。UniFuncs 的实时搜索、网页阅读、深度搜索和深度研究共用一把 `UNIFUNCS_API_KEY`；根据任务选择，用户也可明确指定模式。Starwrite 不自带 UniFuncs HTTP 客户端：调用前必须确认当前 Agent 已连接 UniFuncs MCP，或能经官方 REST API 发起 HTTPS 请求；两者都不具备时说明缺少调用能力，不得声称已完成搜索。用交互式向导说明用途和获取路径；取得用户授权后，只写入其私有配置目录。不得把任何 Key、App Secret、草稿 media_id 写入项目、Git、README、Vercel 或聊天复述中。

公众号发布默认只创建**普通草稿**：不群发、不声明原创。只有用户明确说“发布到草稿箱”且配置完整时才执行发布。

## 事实与研究

只有选题或初稿缺少来源时，先读取 [research-policy.md](references/research-policy.md)。必须先完成 `事实卡片.md`，再写文章：每条可写入正文的事实都要带原始链接、发布日期或访问日期、来源类型和核验状态。来源不够可靠的内容只能作为待核验线索，不能写成事实。

- 轻量产品科普或当前动态：优先 UniFuncs 实时搜索与官方网页阅读。
- 需要多源比较和来源清单：使用 UniFuncs 深度搜索，再回到原始页面复核。
- 深度技术文章：先用 UniFuncs 深度研究收集线索、反例与待核验问题，再回到官方文档、论文、代码仓库逐项复核。
- 用户要求特定个人文风时，才加载 `khazix-writer`。它不是默认依赖。
- 需要中文成文或改稿时，事实卡片完成后再按需加载 `human-writing`；不得把它当成预装前提。

## 多媒体素材

检测到视频链接、本地视频、音频或播客时，按需调用 `video-transcript`：

1. 输出带时间戳的 `视频或播客逐字稿.md`。
2. 首次本地模型下载前，说明需要下载模型和大致磁盘占用，等待用户同意。
3. 将逐字稿中的事实、观点与时间点整理进 `素材整理.md` 和 `事实卡片.md`。

没有多媒体输入时，不调用、不安装，也不下载模型。

## 写作与衍生交付

1. 写清 `任务说明.md`：受众、目的、主题、边界、语气和篇幅。
2. 从核验后的 `事实卡片.md` 写入 `素材整理.md`；说明哪些是事实、机构自述、作者判断和未知项。
3. 生成 `文章母稿.md`。正文保持自然中文，营销表述要标明归属，不把推断写成结论；文末给出精选来源。
4. 从同一母稿生成 `短视频脚本.md`：开头钩子、分镜或画面建议、旁白、结尾行动语；不新增未经核验事实。
5. 需要封面、公众号正文图或小红书卡片时，先读取 [visual-direction.md](references/visual-direction.md)。封面与卡片默认采用用户定义的蓝白高端扁平商业科技风。优先调用 Agent 原生生图能力；仅在原生生图失败、用户指定模型或需要批量生产时，才将 KIE 等 API 作为兜底。
   - 多段内容需要卡片时，先为每张卡片写出编号、小标签、主标题、短副标题、核心观点、图形类型和关键词，再生成一组统一的 3:4 竖版信息图。
   - 3:4 卡片是小红书封面、小红书组图和公众号正文配图共用的主资产。创建公众号 API 草稿时，额外导出同一视觉系统的 2.35:1 宽幅缩略封面；不得拿竖版卡直接充当该缩略封面而任由平台裁切。
   - 用户提供人像照片时，才可将其作为封面输入；没有提供时，不伪造头像或人物。若任务需要讲师/作者形象而用户尚未提供，可主动询问，例如：请用户提供 `@image#1:"最新版讲师人像.png"`。获得人像后，优先用于 2.35:1 公众号缩略封面和短视频首帧/结尾帧。
   - 若图中的中文必须准确，先检查生图文字；错字时交付可编辑的文字层方案，不交付带错字的图片。
6. 调用 `gzh-design-skill` 生成可粘贴公众号的内联样式 HTML。必须保留正文真实 `<img>`，不能只留图片占位；运行其 HTML 校验器，并将最终交付文件命名为 `公众号排版.html`。如需本地图片，改用相对的 `_资源/` 路径。
7. 调用 `html-ppt-skill` 从同一母稿生成录屏 HTML。每页只表达一个观点，至少含封面、问题、核心解释、案例或论据、方法与总结；支持时附 presenter notes；最终入口命名为 `录屏幻灯片.html`，运行资源置于 `_资源/`。
8. 用户明确授权发布且凭证齐全时，调用 `post-to-wechat`，上传封面和正文图，创建普通草稿并记录返回的 `media_id` 到私有运行日志，不写入 Git。

## 交付清单

每次任务完成时，必须在文章项目根目录创建唯一入口 `交付清单.md`。它只列中文文件名、状态和说明，不依赖 Markdown 本地链接；用户直接打开文章项目文件夹即可看到所有主要产物。不得把绝对本地路径、Key、App Secret 或 `media_id` 写入交付清单。

| 类别 | 产物 | 状态与说明 |
| --- | --- | --- |
| 研究过程 | `研究记录.md`、`事实卡片.md` | 查询方式、候选来源、最终采用与未采用原因 |
| 写作 | `任务说明.md`、`素材整理.md`、`文章母稿.md` | 受众、事实边界、内容母稿 |
| 视觉 | `信息图卡-01.png` 至 `信息图卡-03.png`、`公众号缩略封面.png` | 是否使用人像、文字检查结果 |
| 分发 | 公众号 HTML、短视频脚本、录屏 HTML | 校验或浏览器验证结果 |
| 发布 | `发布结果.md` | 正文图上传、封面上传、普通草稿创建是否成功；`media_id` 仅写入私有日志 |

没有执行的模块也要列出并标为“未请求”或“未配置”。完成后在聊天中先报出文章项目目录和 `交付清单.md` 文件名，再用不超过数行说明成功项、失败项和下一步。

## 交付前检查

- `事实卡片.md` 中每个重要事实可回溯，正文未混入未核验线索。
- `文章母稿.md`、公众号 HTML、录屏 HTML 三者的核心结论一致。
- 公众号 HTML 通过 `gzh-design-skill` 校验，且包含真实正文 `<img>`。
- 草稿发布前用本地路径验证封面与正文图片可读；成功只报告“已创建普通草稿”。
- 所有主要产物均位于文章项目根目录，`_资源/` 只含运行依赖；`交付清单.md` 不含 Key、App Secret 或 `media_id`。
- 报告已使用的可选模块、未启用的模块和需要用户后续确认的风险。
